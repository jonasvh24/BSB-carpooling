# DECISIONS

Choices made where the brief left room, with the default applied (§13) or the reasoning.

| # | Decision | Why |
|---|---|---|
| 1 | Repo name `jvcarpool`, app name "Poolmate" in UI (`t.app.name`) | Requested folder name; the brief says the working title is free. |
| 2 | Prisma 6.19 rather than Prisma 7 | Prisma 7 requires driver adapters and `prisma.config.ts`; Prisma 6 keeps `DATABASE_URL="file:./dev.db"` exactly as the brief describes and is the lower-risk pilot choice. Postgres later is a `provider` change plus a migration. |
| 3 | Auth.js sessions use JWT; the Prisma adapter is used only for magic-link tokens and user creation | Lets the proxy check sessions without a database round trip; user rows are still the source of truth (status, role) and are re-read on every request in the app layout. |
| 4 | Users are created by a wrapped adapter that resolves the organisation from the email domain or an `Invitation` row | Multi-tenant from day one without a rewrite; the stock adapter cannot set `orgId`. |
| 5 | Added an `Invitation` model and an `org.goNoGoThresholds` JSON-text column and `org.digestTime` | The brief needs admin-invited addresses (§9.1), editable go/no-go thresholds (§8.2) and an admin-settable digest time (§13) but does not list where they live. |
| 6 | `TripParticipant.userId` is nullable with an `anonymisedId` | Required to anonymise history on account deletion (§9.6) without violating a foreign key. |
| 7 | Gender values `FEMALE | MALE | OTHER` | Needed for same-gender matching; `OTHER` never equals anything but itself. Never displayed. |
| 8 | Language options `nl | fr | en | other` | Brief step 1; "other" is treated as no shared-language signal. |
| 9 | Admin bootstrap emails are also written to `Invitation` | So a pilot owner outside the school's domain can sign in. |
| 10 | Dev mailbox at `/dev/mailbox` (in-memory, last 50) in addition to the console and Mailpit | Lets Playwright drive the real magic-link flow; disabled by `PILOT_MODE=true` (§2.2 "no mailbox route in pilot mode"). |
| 11 | Playwright uses Chromium with a 390 px mobile viewport instead of the WebKit iPhone preset | One browser download; the acceptance criterion is the viewport width, not the engine. |
| 12 | E2E runs on port 3100 against `prisma/test.db` | Port 3000 is often taken by other projects on the pilot laptop; tests must never touch `dev.db`. |
| 13 | Icons are generated by `scripts/make-icons.mjs` (teal square, white ring) | No design assets exist; the script avoids an image dependency and can be replaced by real artwork. |
| 14 | Route announcer aside, only one `role="alert"` per page | Accessibility: errors are announced once. |
| 15 | Holiday week seeded as 2026-11-02 … 2026-11-06 ("Autumn break") | Brief asks for "one holiday week"; Belgian autumn break is the first realistic one after launch. |
| 16 | Match reasons are stored as codes with parameters (`{ code, params }`) and rendered through `src/i18n` | The brief wants NL/FR later; storing rendered English strings in `Match.details` would lock the language in. |
| 17 | Scores are computed from the detour rounded to 0.1 min | So the stored `detourMinAvg` and the stored score always agree with each other and with the per-day details. |
| 18 | Unmatched reason semantics: `NO_DRIVERS` = no counterpart at all; `NO_CANDIDATE_IN_CORRIDOR` = counterparts exist but none passed the corridor prefilter or the routed detour cap; `TIME_MISMATCH`; `CAPACITY`; `NO_SCHEDULE` | The brief lists four reasons; a fifth was needed for completed profiles with no active schedule days. A user's reason is the furthest stage any candidate reached. |
| 19 | Fallback routing applies the 35/55 km/h rule to the whole route distance, not per leg | Per-leg speeds priced a pooled route and its direct baseline differently and produced false "detour too long" rejections. |
| 20 | Existing pools are planned with caps switched off (`enforceCaps: false`); caps are enforced only when adding a member | A rotation driver's own caps differ from the founder's; the weekday plan must always render. |
| 21 | Driver rotation picks the driver by `(isoWeekYear × 53 + isoWeek) mod eligible` over members with seats, ordered by join date | Deterministic per ISO week without storing state; costs net out in the tally. |
| 22 | Cost tally hidden only when every active member chose `ALTERNATE` | Brief: "hidden entirely for pools where members chose ALTERNATE". With mixed preferences the tally is still useful. |
| 23 | Thumbs up after a DONE trip is an `AuditLog` row (`TRIP_THUMBS_UP`) | No rating model in the brief's schema; the audit table already exists and is exportable. |
| 24 | Accepting a lift from a standalone driver creates a `FORMING` pool for them holding the one-day trip | The trip needs a pool; `FORMING` keeps it out of the active-pool metrics. |
| 25 | `Trip.driverId` is nullable with `onDelete: SetNull` | A deleted driver's DONE trips must survive for the impact metrics (§9.6 anonymisation, not deletion). |
| 26 | Digest and verification prompts are idempotent by looking for an existing notification with the trip link | The digest runs at 18:00 and "on app open"; no separate flag column needed. |
| 27 | Reliability: planned = participations with status IN or NO_SHOW on trips that are DONE or NOT_HAPPENED; done = IN on DONE trips | The brief defines the ratio, not the denominators. |
| 28 | Rate limits: sign-in 10/IP and 5/address per 10 min; geo search 60/min; reverse 20/min; requests 20/h; messages 60/h; reports 10/day. In-memory, per process | Single-process pilot (§2.2); swap for Redis if ever multi-instance. |
| 29 | E2E points `OSRM_URL` at a closed port | Tests are offline-safe and deterministic through the haversine fallback; times show "estimates", which is also a visible check of the fallback path. |
| 30 | The pilot-mode e2e server uses `NEXT_DIST_DIR=.next-pilot` | Two `next dev` instances cannot share one `.next` directory. |
| 31 | Users are `ACTIVE` but hidden from matching when their location consent is withdrawn (engine input filters on a current `LOCATION_SHARING` consent) | §9.5 without a status change that would lock them out of the app. |
| 32 | Tomorrow's trips are also materialised on app open, throttled to once per 10 minutes per process | Brief §7.4 "on demand when the app is opened"; the throttle keeps page loads cheap. |
| 33 | Weekly "N colleagues joined near you" counts completed sign-ups within 8 km in the last 7 days | Same 8 km radius as the cold-start message. |
| 34 | Admin bootstrap and invitations: invited addresses are also emailed an invitation via the shared template | Brief §8.2 "adds them to the allowlist and sends invitations". |
| 35 | `scripts/dev/` holds two Playwright helper scripts (screenshots, PWA check) that are not part of `npm test` | Useful for visual checks and the production installability check; documented in `CLAUDE.md`. |
